# Draft PR for softhsm/SoftHSMv2: a private OpenSSL library context (#834)

Status: **draft, not filed; prototype only.** Before opening it:

- **Issue.** Fixes [#834](https://github.com/softhsm/SoftHSMv2/issues/834) ("deadlock in
  softhsm2 when testing head of openssl", open). One commenter there argues it is invalid:
  pkcs11-provider "is not a general purpose provider" and must be listed after default. The
  pkcs11-provider maintainer closed the same report on their side,
  [openssl-projects/pkcs11-provider#723](https://github.com/openssl-projects/pkcs11-provider/issues/723),
  with "This is an issue with softHSM2 using the default libctx, nothing we can do in
  pkcs11-provider". pkcs11-provider's 1.0 release notes say the same of software tokens that
  link OpenSSL "without utilizing a separate libctx". Link both in the PR.
- **Scope.** The prototype converts only the digest and cipher inits that the C_Login traces
  pass through (PBKDF digest, then the AES decrypt of the token key). A PR upstream would want
  the remaining default-libctx sites in `src/lib/crypto/OSSL*.cpp` (about 70 by a rough count:
  `EVP_PKEY_CTX_new*`, `RAND_bytes`, `EVP_PKEY_new_raw_*`, HMAC/CMAC, key generation), and a
  `WITH_FIPS` build loading `fips` instead of `default` into the context. Ask on #834 first
  whether the maintainers want the minimal fix or the full conversion.
- **Test.** No cppunit test can exercise this (it needs pkcs11-provider in-process). PR #907
  added a pkcs11-provider process-exit regression test; a CI job like it running the
  reproducer below would be the natural test.

Checked on 2026-11-14: release 2.7.0 (nixpkgs' build) hangs, and main `7380895` still has no
library context (`src/lib/crypto/`). The patch was made against 2.7.0 and applies to `7380895`
with offsets and fuzz only (OSSLUtil.cpp +108 lines, OSSLUtil.h +11).

**Title:** Do SoftHSM's own crypto in a private OpenSSL library context

**Body:**

Fixes #834.

SoftHSM does its internal crypto through OpenSSL's default library context, fetching
implicitly (`EVP_DigestInit_ex(ctx, EVP_sha256(), NULL)`, `EVP_DecryptInit(ctx, EVP_aes_*(), ...)`).
That context belongs to the application. When the application has loaded pkcs11-provider
pointed at SoftHSM, and that provider was activated before `default`, the implicit fetch picks
pkcs11-provider's implementation, which calls back into SoftHSM. `C_Login` holds `Token`'s
non-recursive `tokenMutex` while it derives and decrypts the token key, so the call back
deadlocks:

    C_Login -> Token::loginUser (locks tokenMutex) -> SecureDataManager::login
      -> RFC4880::PBEDeriveKey -> OSSLEVPHashAlgorithm::hashInit -> EVP_DigestInit_ex
      -> p11prov_digest_init -> p11prov_get_session -> C_OpenSession
      -> SessionManager::openSession -> Token::isSOLoggedIn (locks tokenMutex: hangs)

Blocking pkcs11-provider's digests (`pkcs11-module-block-operations = digest`) only moves it:

    SecureDataManager::login -> OSSLEVPSymmetricAlgorithm::decryptInit -> EVP_CipherInit
      -> p11prov_cipher_decrypt_init -> ... -> C_GetSessionInfo -> Session::getInfo
      -> Token::isSOLoggedIn (hangs)

Provider order should not decide whether a PKCS#11 module deadlocks, and SoftHSM cannot know
what the application loads. This gives SoftHSM its own `OSSL_LIB_CTX` holding only the default
provider, with no configuration file read into it (so pkcs11-provider is never activated there),
and fetches the digests and ciphers from it by name. The fetched implementations are cached for
the life of the module, since callers hold plain `const EVP_MD*`/`const EVP_CIPHER*`. Before
OpenSSL 3, or if the context cannot be made, the old pointers are used unchanged.

Reproduce (needs softhsm2-util, OpenSC's pkcs11-tool, OpenSSL 3, pkcs11-provider):

    softhsm2-util --init-token --free --label t834 --so-pin 5678 --pin 1234
    pkcs11-tool --module libsofthsm2.so --token-label t834 --login --pin 1234 \
      --keypairgen --key-type EC:prime256v1 --id 01 --label k
    PKCS11_PROVIDER_MODULE=libsofthsm2.so openssl pkey \
      -provider pkcs11 -provider default \
      -in 'pkcs11:token=t834;object=k;type=private?pin-value=1234' -pubout

Before: hangs in `C_Login`. After: prints the public key. (It then crashes at process exit in
`C_CloseSession`, which is #780, fixed on main by #897.)
