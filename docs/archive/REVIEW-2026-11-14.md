- `source_target` and `realised_target` differ only in their message. `locked_spki` decodes what

## Why the tests missed these

- The dry-run property is written by hand in each test, for one verb and one kind of object;
  no invocation gets it automatically. Key files were never dry-run, and public objects were
  never exported, only migrated.
- The test matrix is tokens by key types. The crossings that broke are flags by destinations.
- Every reference token offers RFC 5649 and each curve's ECDSA hash, so a plan that assumed
  less was never contradicted.
- Nothing measures which dispatch arms a test reaches (coverage and mutation testing are open
  in OPEN.md).

What would catch the class: a dry-run twin in the test harness (every real invocation preceded
by its `--dry-run` form, asserting the lock and token unchanged and the verdict equal); a test
that walks the clap command tree and fails on a verb or flag no integration test uses; and
reference tokens degraded on purpose through the mechanism deny list the harness already has.
