# Refactor plan, 2026-11-12 (code review of c58cb2b)

Source: the code review of c58cb2b (lines of code, simplifications, Rust features, crate
boundaries). Each item lands as its own commit, followed by the usual `CHECKPOINT: record <sha>`
commit. Status lives in the table; details and decisions are under each item.

**Invariant for every item:** identities, spec digests and the lock format stay byte-identical,
except where an item says it changes a format or an exit code, and says why.

**Gates per commit:**
- `nix flake check` (SoftHSM, tpm2, p11-kit, unit tests, VM tests) and `nix build .#test-nspawn`.
- The read-only YubiKey verify of `examples/yubikey-secureboot.toml` (6 specs).
- **Cross-version check (R0).** Locks written by c58cb2b for every object class must still pass
  `verify` and `realise --no-update-lock` with the new build. The integration tests cannot catch
  format drift, because they write their locks with the code under test.

## R0: cross-version harness

- Build c58cb2b's binary to a scratch link.
- Record one object of every class on a scratch SoftHSM token:
  - EC private key (pop-sign), RSA private key (pop-decrypt), Ed25519 private key;
  - public key, certificate, data object;
  - AES secret key (CMAC + KCV), generic-secret HMAC key;
  - a `publicAttributes` spec and an `ALLOWED_MECHANISMS` spec.
- After each item, run `verify` and `realise --no-update-lock` with the new binary against that
  lock. Then run `realise --update-lock` on a copy and require the file to stay byte-identical,
  `observed`/`provenance` excepted.
- Script: `scripts/xversion.sh` (kept in the repo so later work can reuse it).

## R1: small fixes

- `LazyLock` replaces the `OnceLock` + `get_or_init` functions in ykcs11.
- `Lock::realisation(spec, token)` replaces four copies of
  `.realisations.get(spec).and_then(|m| m.get(token))`.
- `Token` keeps one sorted mechanism-name list. `warn_provenance` stops recomputing it for every
  locked mechanism, which was quadratic.
- `impl Display for Target` instead of `what() -> String`.
- `Display` for `Locator` and `Immutables` instead of `serde_json::to_string(..).unwrap_or_default()`
  in error text. The messages must keep their content; tests grep stderr.

## R2: one boolean-attribute table

Five places name the same booleans:
- `bool_attr`: name → constructor;
- `policy_attr_type`: name → type, panicking through `unreachable!`;
- `attr_bool`: attribute → bool;
- `COMMON_ATTRS` and `declarable(class)`: what a spec may set;
- the per-class lists in `Token::policy`: what is observed.

These are **different sets**:
- `CKA_TOKEN` is observed but not declarable.
- The `*_RECOVER` attributes are declarable on secret keys but not observed there.
- `LOCAL`, `NEVER_EXTRACTABLE` and `ALWAYS_SENSITIVE` are immutables only.

The single table therefore carries two per-class sets, *observed* and *declarable*. The observed
set must reproduce today's vectors exactly, or recorded `policy` tables change.

## R3: one signature verifier

There are three verifiers today:
- `core::pop::verify`: raw `r‖s`, `normalize_s`, the curve's hash, P-256/384/521, secp256k1,
  brainpool, Ed25519, RSA-SHA256.
- ykcs11 `verify_signed_by`: DER ECDSA, hash from the certificate's OID, three copy-pasted RSA arms.
- tpm2 `verify_signature`: separate `r` and `s`, P-256, ECDSA-SHA256 over the message.

`core::sig` provides:
- `ecdsa_prehash(spki, digest, Encoding::Raw | Der)`, a macro over the curves;
- `rsa_pkcs1v15::<D: Digest>(spki, msg, sig)`.

Both return `Result<bool>`, with parse failures as a neutral error. Each caller keeps its own
`Conflict` wording.

## R4: edition 2024

- `edition = "2024"` and `rust-version = "1.89"`. The code already needs `File::lock` (1.89),
  `as_chunks_mut` (1.88) and `is_none_or` (1.82). The Nix build uses rustc 1.99.
- `cargo fix --edition` first. The known breaks are `let gen` (a reserved keyword) and
  `std::env::set_var` in tests (now `unsafe`).
- Let chains flatten the nested `if let … { if … }` sites.

## R5: typed classes, key types and schemes

- `enum ObjectClass` and `enum KeyType` in core, with `#[serde(rename = "CKO_…")]`;
  `ObjectCfg.key_type` becomes `Option<KeyType>`, omitted exactly when the string is empty today.
  - The serialized form and every spec digest stay identical (pinned tests).
  - `Commit::label` formats the key type into the commitment input, so its `Display` must be the
    exact `CKK_…` name (pinned KATs).
  - **Exit-code change:** an unknown class or key type name is now invalid at load (17). It used to
    fail when first used (15). No test depends on 15 for an unknown name.
- `enum Scheme` for the constants (`KNOWN`, `COMMITMENT`, `ATTESTATION`, `DEPRECATED`, the
  attestation kinds), with `as_str()`.
  - The lock's `ids` and `schemes` stay `String`-keyed: a scheme from a newer cakeys must still load
    and warn, and the map order decides which `got:` line prints first.

## R6: core errors

- `KmError::Io(String)` (exit 1, as I/O errors exit today).
- `load_config`, `load_lock`, `save_lock` and `lock_for_update` return `cakeys_core::Result`.
- `anyhow` leaves core's dependencies.

## R7: the pure model in core; reconcile split

- `Target`, `plan_mode`, the binding checks, `declared_commits`, `Resolved` and `reconcile` are
  pure config and lock logic. With R5's enums they need no `cryptoki`, so they move to
  `cakeys_core::plan` and `cakeys_core::reconcile`.
- The move is first a pure move with no logic change, gated on its own.
- Then the split:
  - `compare(&Lock, &Target, &Resolved, LockWrite, &mut Notes) -> Result<()>`: the checks in today's
    order, since order decides the exit code. `update` skips only the spec-change and policy-drift
    checks.
  - `record(&mut Lock, …) -> bool`.
  - `verify` no longer clones the lock.
- `enum LockWrite { Compare, Record }` replaces the `update: bool` parameters.
- **Notes as data:** `Notes` (a `Vec<Note>`) is passed in by the CLI and printed by it on success
  *and* on error, before the error line. Today's notes print before an error is returned, and
  the text stays the same. Token-side messages ("created", rollback, "destroyed") go through
  `Notes` too.
- Unit tests for the lock rules in core: downgrade, drift, first use, attestation anchor, deprecated.

## R8: `check` into ops

`ops::check(reference, …)` owns the scheme gating and the locked-scheme rule, and the CLI arm
becomes a call plus `println!`.

## R9: split token.rs

`token/` with `mod.rs` (open, session, SO), `find.rs`, `policy.rs`, `generate.rs`, `identity.rs`
(ids, spki, commitments, wrap-rebind), `pop.rs` and `uri.rs`. `cakeys_pkcs11::token::ModuleInfo`
stays re-exported; the providers and the example import it.

## R10: crates and features

- `softhsm` (11 lines) and `p11-kit` (14 lines) become `cakeys_pkcs11::providers::{SoftHsm, P11Kit}`.
  Their crates are removed.
- `cli` features: `tpm2` and `ykcs11`, both on by default.
  - `tests/tpm2.rs` needs `required-features = ["tpm2"]`.
  - New check: `cargo check -p cakeys --no-default-features`.

## R11: provider options (format change, last)

`tcti`, `tpm2Store` and `akHandle` leave core's `TokenCfg`. They move to a per-token table that the
provider deserializes into its own struct:
```toml
[tokens.tpm.options]
tcti = "device:/dev/tpmrm0"
```

- **This changes keys.toml syntax.** Today `deny_unknown_fields` catches a typo in these fields at
  load.
- To keep that:
  - each provider rejects unknown option fields itself (17);
  - an `options` table on a provider that takes none is refused (17).
- Docs, examples and tests are updated, and the final report names the change.
